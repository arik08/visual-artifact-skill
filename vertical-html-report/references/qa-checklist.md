# 제출 전 체크리스트

자동 검사 2개를 먼저 돌리고, 나머지는 눈으로 확인한다.

```
python scripts/build_report.py 보고서.body.html        # 린트: ERROR 0 필수
python scripts/render_check.py 보고서.html             # 렌더 검사 + 스크린샷 (Chrome/Edge 필요)
python scripts/render_check.py 보고서.html --width 500 # 모바일 레이아웃 확인(선택)
```
브라우저에서 `보고서.html?qa`로 열면 오류·경고 패널이 표시된다.

## A. 내용 (가장 중요)
- [ ] 표지 부제 또는 요약 첫 줄만 읽어도 결론을 알 수 있다 (숫자 포함)
- [ ] 핵심 메시지 3개가 서로 겹치지 않고(MECE) 각각 본문 섹션과 대응한다
- [ ] 섹션 `.rk-lead`와 모든 차트·표 제목이 결론형이고 숫자가 있다
- [ ] 요청·결정 사항이 있다면 기한·담당·미결정 시 영향이 적혀 있다
- [ ] 각 섹션 끝에 시사점(`.rk-sowhat`) 또는 조치가 있다
- [ ] 제목만 순서대로 읽어도 이야기가 이어진다

## B. 숫자
- [ ] 모든 숫자는 사용자 데이터에서 왔거나 그로부터 계산했다 (지어낸 숫자 없음)
- [ ] 예시 수치를 썼다면 `"sample": true`이고, 전달 메시지에서 밝혔다
- [ ] 파생 수치(증감률·비중·합계)를 검산했다 — 합계 = 부분의 합, 비중 합 ≈ 100%
- [ ] 요약의 숫자가 본문·차트와 정확히 같다
- [ ] 단위·비교 기준·기간이 모든 수치에 있다. %와 %p를 구분했다
- [ ] 단위(억원/백만원), 날짜 형식, 감소 표기(-/△)가 문서 전체에서 통일
- [ ] 추정·전망·미확인 사항은 "추정", "전망", "확인 중"으로 표시

## C. 시각화
- [ ] 각 차트는 한 가지 메시지를 보여주고, 그 대상이 `highlight`되어 있다
- [ ] 숫자 1~3개짜리 차트가 없다(→ KPI 카드)
- [ ] 파이 ≤ 6조각, 계열 ≤ 5개, 3D 없음, 보조축은 %에만
- [ ] 모든 차트·표에 `source`(출처·기준일)
- [ ] 스크린샷에서: 라벨 겹침·잘림 없음, 빈 차트 없음, 빨간 오류 박스 없음
- [ ] 나란히 비교하는 차트는 같은 축 범위
- [ ] 참고문헌(`ol.rk-refs`)에 출처·발행일·URL. 추정·역산 값은 차트 note에 방법 한 줄
- [ ] 부록에 계산 과정(숫자 ÷ 숫자 = 결과) 나열이 없다 — 추정 모델만 공식 1줄 + 가정
- [ ] 같은 종류 차트가 3개 이상 연속되지 않는다

## D. 문체
- [ ] 개조식(~함/~임/~예정). 서술식(~습니다/~했다) 없음
- [ ] "크게/대폭/상당히" 같은 모호어 뒤에 숫자가 있다
- [ ] 한 줄 한 메시지, 불필요한 서론·반복 없음
- [ ] 맞춤법·띄어쓰기, 고유명사·부서명 정확

## E. 형식
- [ ] 린트 ERROR 0, WARN은 모두 읽고 판단했다
- [ ] 인쇄 버튼은 사용자가 요청한 경우에만 (`toolbar: print`)
- [ ] 보안등급 배지(대외비 등)가 필요한지 확인
- [ ] 파일명: `YYYYMMDD_보고서명.html` 형태 권장
