# 보고서 유형별 구조와 추천 시각화

템플릿 생성: `python scripts/new_report.py --type <유형> -o 경로/이름.body.html`
(유형: `monthly` `status` `proposal` `incident` `analysis` `blank`)

모든 유형 공통 골격: **표지 → 핵심 요약(결론·메시지 3개·KPI·요청) → 본문 섹션 3~6개 → (의사결정/향후 계획) → 부록·각주**

---

## 1. 실적 보고 (주간·월간·분기) — `monthly`

| 섹션 | 담을 내용 | 추천 시각화 |
|---|---|---|
| 핵심 요약 | 달성률·전기 대비·한 줄 평가, 요청 | KPI 카드 4개(`progress`, `delta`, `spark`) |
| 1. 종합 실적 | 목표 대비 실적, 전년 대비 | `bullet`(여러 KPI) 또는 JSON 표(`bar`·`delta` 열) |
| 2. 매출 분석 | 추이·구성·순위 | `bar`+`highlight`+`target`, `line`+`forecastFrom`, 가로 `bar` 순위 |
| 3. 손익 분석 | 이익 증감 요인 | `waterfall`, `combo`(매출+이익률) |
| 4. 부문/채널별 | 부문 간 비교 | JSON 표(`heat`, `badge`), `stack:"percent"` |
| 5. 이슈 및 대응 | 미달 원인·조치 | `.rk-callout rk-warn`, `rk-gae` 목록 |
| 6. 차기 계획 | 목표·핵심 과제 | `rk-steps` 또는 표 |

체크: 모든 숫자에 비교 기준(목표·전년·전월), 미달 항목은 원인과 조치를 반드시 함께.

## 2. 현황·진척 보고 (프로젝트, 운영 현황) — `status`

| 섹션 | 내용 | 시각화 |
|---|---|---|
| 핵심 요약 | 전체 상태(신호등)·일정 영향·요청 | KPI(공정률 `progress`, 예산 집행률, 이슈 수 `status`) |
| 1. 추진 경과 | 완료/진행/예정 | `rk-timeline` 또는 `rk-steps`(done/now) |
| 2. 일정 | 계획 대비 진척·지연 | `gantt`(`today`, `progress`, `milestone`) |
| 3. 예산·자원 | 집행률 | `.rk-progress` 여러 줄, `bullet` |
| 4. 이슈·리스크 | 영향도·대응 상태 | JSON 표(`badge` 상태 열), `heatmap`(발생가능성×영향도) |
| 5. 향후 계획·요청 | 다음 2~4주 과제, 의사결정 필요사항 | `rk-decision`, 표 |

체크: 상태 판단 기준(예: 일정 지연 1주 이내=주의, 2주 이상=위험)을 각주에 명시.

## 3. 기획·제안 / 의사결정 요청 — `proposal`

| 섹션 | 내용 | 시각화 |
|---|---|---|
| 핵심 요약 | 제안 내용·투자액·기대효과·**승인 요청과 기한** | KPI(투자, 효과, 회수기간) + `rk-ask` |
| 1. 배경·필요성 | 문제의 크기(숫자) | `line`/`bar` 추세, `rk-callout` |
| 2. 현황·원인 | As-Is 문제, 원인 분해 | `pareto`, `rk-compare`, Mermaid(현행 프로세스) |
| 3. 대안 비교 | 2~3개 대안의 비용·효과·리스크 | JSON 표(권고 열 강조), `scatter`+`quadrant`(효과×난이도) |
| 4. 추진 방안 | 권고안 상세, To-Be | `rk-compare`, Mermaid(개선 프로세스), `rk-steps` |
| 5. 기대 효과·소요 예산 | 정량 효과, 투자 회수 | `waterfall`(효과 분해), `combo`(누적 효과 vs 투자), `bar`+`role` |
| 6. 일정·리스크 | 로드맵, 리스크·대응 | `gantt`, 리스크 표 |
| 의사결정 요청 | 결정 사항·기한·미결정 시 영향 | `rk-decision` |

체크: 대안 2~3개, 권고안 표시, "미결정 시 영향" 기재, 효과 산식을 부록에.

## 4. 결과 보고 (행사·캠페인·프로젝트 종료) — `analysis` 또는 `monthly` 응용

배경·목표 → 추진 경과(`rk-timeline`) → 성과(목표 대비: `bullet`, KPI) → 잘된 점/미흡한 점(`rk-grid` 카드 2개) → 후속 조치·교훈.

## 5. 이슈·사고 보고 — `incident`

| 섹션 | 내용 | 시각화 |
|---|---|---|
| 핵심 요약 | 무엇이·언제·영향 범위·현재 상태·조치 | KPI(영향 고객 수, 장애 시간, 손실 추정) + 상태 배지 |
| 1. 발생 개요 | 일시(24시간제)·장소·시스템·발견 경위 | 정의 목록 표 |
| 2. 경과 (타임라인) | 분 단위 경과 | `rk-timeline`, Mermaid `sequenceDiagram` |
| 3. 영향 | 범위·규모 | `line`(지표 급락 구간 `annotations`), 표 |
| 4. 원인 | 직접 원인·근본 원인(5 Whys) | Mermaid `flowchart TD`, `rk-gae` |
| 5. 조치 | 완료/진행/예정 | JSON 표(`badge`) |
| 6. 재발 방지 | 대책·담당·기한 | 표, `rk-steps` |

체크: **확인된 사실과 추정을 구분**("추정", "확인 중" 표기), 시각 24시간제, 책임 추궁보다 사실·조치 중심.

## 6. 데이터·시장·경쟁 분석 — `analysis`

| 섹션 | 내용 | 시각화 |
|---|---|---|
| 핵심 요약 | 핵심 발견 3개와 시사점 | KPI, 히어로 숫자 |
| 1. 시장 규모·성장 | 규모 추이, 전망 | `bar`/`line`+`forecastFrom` |
| 2. 경쟁 구도 | 점유율 변화, 포지셔닝 | `slope`, `scatter`+`quadrant`, `radar`(≤3사) |
| 3. 고객 분석 | 세그먼트·행동 | `stack:"percent"`, `funnel`, `heatmap`, `sankey` |
| 4. 원인·동인 분석 | 상관·분포 | `scatter`+`trend`, `boxplot`, `histogram` |
| 5. 시사점·제언 | 전략 방향 | `rk-swot`, `rk-matrix`, `rk-callout rk-insight` |
| 부록 | 데이터 정의·출처·방법론 | 표 |

체크: 표본 수(n), 조사 기간, 출처를 모든 차트에. 상관 ≠ 인과.

## 7. 주간 업무 보고 (간단형) — `blank` 응용

요약(이번 주 핵심 3줄) → 완료 업무(표: 업무·결과·상태 배지) → 진행 중(진척 `progress`) → 다음 주 계획 → 이슈·협조 요청. 차트는 0~2개면 충분.

| 일반 보고 | 4~6 | 4~8 | 3~5 |
| 심층 분석 | 6~8 + 부록 | 8~14 | 4~5 |
