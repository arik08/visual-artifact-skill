## 1. 작성 전: 세 가지를 먼저 정한다

1. **독자와 판단**: 누가 읽고 무엇을 결정하는가? (예: 대표이사가 단가 인상을 승인할지)
2. **한 줄 결론(Big Idea)**: 숫자가 들어간 한 문장. 이것이 표지 부제·요약 첫 줄이 된다.
3. **근거 3개**: 결론을 받치는 서로 겹치지 않는(MECE) 메시지 3개 → 각각 본문 섹션 1개.

> 한 줄 결론을 못 쓰면 아직 쓸 준비가 안 된 것이다. 데이터를 더 보거나 사용자에게 목적을 묻는다.

## 2. 구조

**두괄식**: 결론 → 근거 → 세부. 독자는 첫 화면(표지+요약)만 보고 판단할 수 있어야 한다.

**피라미드**: 결론 아래 근거 3개(최대 5개), 각 근거 아래 데이터. 모든 아래 단계는 위 단계의 "왜?/어떻게?"에 답한다.

**SCQA** (요약의 결론 문장이나 기획 보고서 도입에 사용):
- S 상황: 독자가 이미 동의하는 사실 — "온라인 매출은 3년간 연 15% 성장"
- C 문제: 변화·문제 — "3분기 고객 획득비용(CAC)이 전분기 대비 32% 상승"
- Q 질문: (생략 가능) — "수익성을 어떻게 회복할 것인가?"
- A 답: 권고안 — "채널 예산 재배분으로 4분기 내 CAC를 2분기 수준으로 낮출 것을 제안"

**MECE (빠짐없이, 겹침없이)**: 원인·대안을 나눌 때 검증된 분해 틀을 쓴다.
- 매출 = 판매량 × 단가 × 믹스 / 고객 수 × 객단가 × 구매 빈도
- 내부 / 외부, 단기 / 중기 / 장기, 사람 / 프로세스 / 시스템
- 테스트: 한 데이터가 두 항목에 동시에 들어갈 수 있으면 겹친 것이다. 다 못 나누면 "기타"를 명시.

## 3. 제목 = 액션 타이틀

제목만 이어 읽어도 보고서 전체 이야기가 되어야 한다. 섹션 `h2`는 짧은 주제명, 바로 아래 `.rk-lead`와 모든 차트 `title`은 **결론**.

| ✗ 주제형 | ✓ 결론형 |
|---|---|
| 월별 매출 추이 | 매출은 3분기 이후 3개월 연속 감소, 9월 전년 대비 -12% |
| 채널별 CAC | 유료 검색 CAC가 타 채널의 2.1배 — 예산 재배분 필요 |
| 고객 이탈 현황 | 이탈의 68%가 가입 후 90일 이내에 집중 |
| 리스크 요약 | 납기 지연 리스크 3건 중 2건은 10월 말까지 해소 가능 |
| 프로젝트 일정 | 개발 2주 지연, 추가 인력 투입으로 오픈일(3/2)은 유지 |

규칙: 숫자 1개 이상 · 방향(증가/감소/유지) · 비교 대상 · 2줄 이내(약 40자). 상관관계만 있으면 "때문에" 대신 "동반", "연관".
차트는 제목을 **눈으로 증명**해야 한다 → 제목이 말하는 항목을 `highlight`.

## 4. 문장 = 개조식 + 해설 단락

보고서는 **개조식(빠른 판단)과 해설 단락(이해·설득)을 섞는다**. 차트·표·목록만 있고 문장이 없으면 독자는 숫자 사이의 인과와 의미를 스스로 추론해야 한다.

**해설 단락(`<p>`) 쓰는 법**
- 섹션마다 2~3개, 각 3~5문장(약 150~300자), 섹션 합계 400~800자. 리드 다음(맥락·원인), 차트 사이(해석), 시사점 앞(의미·영향)에 배치한다.
- 순서: 무엇이 일어났나(숫자) → 왜(원인·배경) → 그래서(의미·영향). 차트 내용을 그대로 읽어주는 문장은 쓰지 않는다.
- 문체: 평서문 "~이다/~했다/~로 보인다"(근거 없는 추정은 "추정된다"). "~습니다"체·대화체 금지. 한 문서 안에서 통일.
- 예: "중국의 조강 생산은 2년 연속 줄었지만 철강재 수출은 오히려 사상 최대인 1억1,902만t을 기록했다. 부동산 경기 부진으로
  내수가 위축되자 남는 물량이 해외로 밀려난 결과다. 감산이 곧 수출 감소로 이어지지 않는다는 점에서 공급과잉은 단기간에 해소되기 어렵다."

**개조식** (요약·목록·표 주석·KPI 설명)

- 명사형·간결체로 끝낸다: **~함, ~임, ~됨, ~필요, ~예정, ~추진, ~요청, ~확인**.
- 서술식(~습니다, ~했다, ~것으로 보입니다)을 섞지 않는다 — LLM이 가장 많이 하는 실수.
- 한 항목 = 한 메시지, 한 줄(약 45자) 이내. 숫자와 핵심어를 앞에.
- 인과는 `→`로 압축: "원재료비 +9% → 영업이익률 -1.1%p"
- 위계 기호(`ul.rk-gae`): □ 대항목 → ○ 중항목 → - 소항목 → · 세부, 참고·근거는 ※(`.rk-note`)

| ✗ | ✓ |
|---|---|
| 최근 매출이 많이 줄어든 것으로 보이며 대응이 필요할 것으로 생각됩니다. | 9월 매출 82억원, 전년 동월 대비 -12% → 4분기 프로모션 예산 5억원 증액 필요 |
| 고객 만족도가 향상되었다. | 고객 만족도(NPS) 41 → 48점, 전 분기 대비 +7점 |
| 다양한 요인으로 인해 비용이 상승함 | 비용 상승 요인: 원재료비 +31억원, 인건비 +12억원, 물류비 +5억원 |

## 5. 숫자·단위·표기 규칙

**단위**
- 한국식 자릿수: 만(10⁴)·억(10⁸)·조(10¹²). "1,234억원", "1조 2,340억원". 헤드라인에 "1,234,000,000원" 금지.
- 표·차트 하나에는 단위 하나. 단위는 `unit`(→ "(단위: 억원)") 또는 열 머리글에.
- "억원"/"억 원" 등 띄어쓰기는 문서 안에서 통일.

**비교 기준은 반드시 함께**
- 전년 동기 대비(YoY), 전 분기 대비(QoQ), 전월 대비(MoM), 전주 대비(WoW), 목표 대비, 누계(YTD).
- 본문은 한국어("전년 동기 대비"), 표 머리글·배지는 약어 허용. 기준 시점 표기: "'25.3Q vs '24.3Q".

**% vs %p**
- 수준의 변화율 → %: 매출 100 → 112 = +12%
- 비율 사이의 차이 → %p: 점유율 20% → 23% = +3%p, 이익률 8.9% → 7.8% = -1.1%p
- "이익률 1.1% 하락"(✗) → "이익률 1.1%p 하락"(✓)

**감소 표기**
- 재무·공공 문서: △12억원 (△ = 마이너스). 차트도 맞추려면 `"negative":"triangle"`.
- 대시보드·일반 문서: -12억원 또는 ▼12억원.
- 한 문서에 한 방식. "△12% 감소"처럼 기호와 단어를 중복하지 않는다.

**반올림·날짜**
- 비율은 소수 1자리, 억원은 정수(10억 미만은 소수 1자리) 정도로 통일. 합계가 안 맞으면 각주 "※ 반올림으로 합계 불일치".
- 날짜: 2026.11.06 또는 2026-11-06 중 하나. 분기: '26.3Q 또는 2026년 3분기. 시각은 24시간제.
- 회계연도 ≠ 달력연도면 첫 등장 시 명시.

## 6. 증감 색과 화살표

| 방식 | 언제 | 설정 |
|---|---|---|
| **성과 기준(기본)** — 좋음=초록, 나쁨=빨강 | 사내 실적·KPI 대부분. 비용·불량률·이탈률은 **증가가 나쁨** → `good:"down"` | `delta: semantic` (기본) |
| **증시 관례** — 상승=빨강, 하락=파랑 | 주가·지수·환율·원자재 가격 등 **시장 데이터**만 | front matter `delta: market` |

- 한 문서에서 두 방식을 섞지 않는다.
- 색만으로 의미를 전달하지 않는다: 키트가 ▲▼ 기호를 함께 붙인다(색각이상·흑백 인쇄 대응).
- 상태(신호등): 정상/주의/위험 = `good`/`warn`/`bad`. 범주색(차트 계열색)과 섞어 쓰지 않는다.

## 7. 데이터 스토리텔링 원칙

1. **맥락 먼저**: 무엇을 결정하게 할 것인가 → 그 판단에 필요한 데이터만.
2. **초점(focus)이 정리(declutter)보다 효과가 크다**: 회색 바탕 + 강조색 1개(`highlight`) + 결론 제목. (Northwestern 연구: 강조가 이해도를 유의하게 높임)
3. **숫자 1~3개는 차트가 아니라 큰 숫자**(KPI 카드). 단일 막대 차트 금지.
4. **정확한 비교가 필요하면 막대**, 시간은 선, 구성은 누적 막대(파이는 6조각 이하·한 개의 메시지일 때만).
5. **막대는 0부터**(키트가 강제). 꺾은선은 변동을 보여야 하면 0 생략 가능(자동).
6. **같은 비교는 같은 축 범위**: 나란히 놓은 두 차트가 같은 지표면 `yMax`를 맞춘다.
7. **IBCS 표기 통일**: 실적=진한 막대, 계획=외곽선, 전망=빗금, 전년=회색 — 문서 전체에서 같은 의미 = 같은 모양(`role` 사용).
8. **직접 라벨**: 끝점 라벨·막대 값 라벨이 범례보다 빠르다(키트 기본값).
9. **출처·기준일**: 모든 차트/표 아래. 추정치는 "추정", 예시는 "예시 데이터".
   - 계산 과정은 쓰지 않는다. 비율·증감률·합계·차감 같은 자명한 계산은 산식 없이 결과만. 역산·추정은 `note`에 방법 한 줄("상반기−2분기로 역산").
   - 부록에 '산식' 목록을 만들어 숫자 대입 과정을 나열하지 않는다(검산은 작성자의 일이지 독자의 일이 아님).
   - 예외: 결론을 좌우하는 **추정 모델**은 부록에 공식 1줄 + 핵심 가정·한계만 쓴다. 숫자 대입 예시는 넣지 않는다.
10. **so what**: 차트마다 `insight` 한 줄 또는 섹션 끝 `.rk-sowhat` — 데이터 → 판단·조치로 연결.

## 8. LLM이 자주 하는 실수와 방지책

| 실수 | 방지책 |
|---|---|
| 숫자 없는 모호한 표현 ("크게 증가", "상당히 개선") | 숫자 + 기준 + 기간. 린트가 '크게/대폭/상당히/다소' 를 숫자 없이 쓰면 경고 |
| 서술식 문장·군더더기("~라고 할 수 있습니다", 소제목 반복) | 개조식, 한 줄 한 메시지. 판단에 영향 없는 문장은 삭제 |
| 단위 혼용(억원/백만원, %/%p, 날짜 형식) | §5 규칙. 최종 점검 시 한 번 더 확인 |
| **데이터 지어내기** | 사용자 데이터만. 계산한 수치는 검산. 예시는 `sample:true` + 전달 시 고지 |
| 차트 과다·장식용 차트 | 핵심 메시지당 1개. 제목(결론)을 못 쓰는 차트는 삭제 |
| 주제형 제목 | 액션 타이틀(§3). 린트가 "~현황/추이"로 끝나고 숫자 없는 제목 경고 |
| 상관을 인과로 서술 | "동반", "연관"으로 |
| 요약과 본문 숫자 불일치 | 숫자는 한 번 정하고 재사용. 린트가 요약 수치가 본문·데이터에 있는지 검사 |
| 출처 누락 | 모든 차트·표에 `source` |
| 색만으로 의미 전달 | 키트의 ▲▼·배지·라벨 사용 |
| 보라색 그라데이션·이모지 아이콘·과한 그림자 등 'AI 티' 나는 장식 | 키트 컴포넌트만 사용. 이모지 금지(필요하면 배지·기호) |
