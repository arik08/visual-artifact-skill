# 다이어그램 가이드 — 프로세스·흐름·조직·시퀀스

## 무엇으로 그릴까

| 내용 | 도구 |
|---|---|
| 일직선 단계 3~6개 (진행 상태 표시) | `ol.rk-steps` (CSS, 가장 안정적) |
| 날짜가 있는 경과·계획 | `ol.rk-timeline` 또는 `gantt` 차트 |
| 분기(조건)·합류가 있는 업무 흐름, 의사결정 트리 | Mermaid `flowchart` |
| 주체 간 주고받는 순서(시스템 연동, 장애 대응, 승인 요청) | Mermaid `sequenceDiagram` |
| 조직도, 시스템 구성도, 원인 분해(로직 트리) | Mermaid `flowchart TD` |
| 상태 변화(주문 상태 등) | Mermaid `stateDiagram-v2` |
| 아이디어 구조 | Mermaid `mindmap` |
| 양(量)의 흐름 | `sankey` **차트** (Mermaid 아님) |
| 일정 | `gantt` **차트** (Mermaid gantt보다 깔끔) |

## Mermaid 사용법

```html
<div class="rk-diagram" data-title="결론형 제목 — 예: 승인 단계 4→3단계로 단축, 처리기간 5일→2일" data-source="구매 규정 개정안">
  <script type="text/x-mermaid">
  flowchart LR
    A["구매 요청"] --> B{"5천만원 이하?"}
    B -- "예" --> C["팀장 전결"]:::brand
    B -- "아니오" --> D["본부장 승인"]
    C --> E["발주"]
    D --> E
    E --> F["검수·지급"]:::good
  </script>
</div>
```
- 반드시 `<script type="text/x-mermaid">` 안에 쓴다(`<`, `>`, `&`를 이스케이프할 필요 없음).
- 테마 색·폰트는 자동. 직접 `%%{init}%%`나 `style`로 색을 바꾸지 않는다.
- 렌더링 후 우측 상단에 **크게 보기** 아이콘이 자동으로 붙는다(휠 확대/축소·드래그 이동·더블클릭 맞춤·Esc 닫기). 끄기: `data-zoom="off"`.
- 속성: `data-title`, `data-subtitle`, `data-source`, `data-max-width="600px"`(너무 크게 보일 때), `data-plain`(테두리 없음).

### 미리 정의된 강조 클래스 (flowchart에서 `:::이름`)

| 클래스 | 모양 | 용도 |
|---|---|---|
| `brand` | 진한 브랜드색, 흰 글씨 | 핵심 단계·변경된 단계 |
| `accent` | 강조색, 흰 글씨 | 주의 지점 1곳 |
| `soft` | 옅은 브랜드색 | 일반 강조 |
| `good` / `warn` / `bad` | 초록/주황/빨강 테두리 | 완료·정상 / 주의 / 문제·병목 |
| `muted` | 회색 | 범위 밖·폐지 단계 |
| `decision` | 연노랑 | 판단 지점 |

사용: `C["팀장 전결"]:::brand` 또는 마지막 줄에 `class C,D brand`.

### 반드시 지킬 문법 규칙 (오류의 90%)

1. **노드 ID는 영문·숫자**(`A`, `B1`, `step2`), 화면 글자는 라벨로: `A["구매 요청"]`.
2. **라벨은 항상 큰따옴표**: 괄호·콜론·슬래시·%·& 등이 있으면 따옴표 없이는 깨진다. `A["매출(억원)"]` ○ / `A[매출(억원)]` ✗
3. 줄바꿈은 `<br>`: `A["구매 요청<br>(현업)"]`
4. 엣지 라벨도 따옴표: `B -- "예" --> C` 또는 `B -->|"예"| C`
5. 소문자 `end`를 노드 ID로 쓰지 않는다(예약어) → `done`, `End`.
6. 모양: `["사각"]`, `("둥근")`, `{"마름모: 판단"}`, `[("DB")]`, `(("원"))`, `[["서브루틴"]]`
7. 방향: 가로 `LR`은 노드 5~6개까지(넘으면 글자가 작아짐) → 그 이상은 세로 `TD`.
8. 노드는 15개 이하. 넘으면 다이어그램을 나누거나 `subgraph`로 묶는다.
9. `subgraph` 이름도 따옴표: `subgraph S1["1단계: 접수"] … end`

### 예시

**의사결정·원인 분해 (로직 트리)**
```
flowchart TD
  P["영업이익 -13억원"] --> R1["매출 요인 +37억원"]:::good
  P --> R2["원가 요인 -43억원"]:::bad
  P --> R3["판관비 요인 -7억원"]
  R2 --> R21["원재료 단가 +9%"]
  R2 --> R22["환율 +6%"]
```

**조직도**
```
flowchart TD
  CEO["대표이사"]:::brand --> S["전략기획실"]
  CEO --> B1["영업본부"] & B2["생산본부"] & B3["경영지원본부"]
  B1 --> T1["국내영업팀"] & T2["해외영업팀"]
```

**시스템 연동 순서**
```
sequenceDiagram
  participant U as 사용자
  participant W as 웹서버
  participant E as ERP
  U->>W: 주문 요청
  W->>E: 재고 조회
  E-->>W: 재고 있음
  W-->>U: 주문 완료
  Note over W,E: 응답 2초 이내 (SLA)
```
- `->>` 실선 요청, `-->>` 점선 응답, `Note over A,B: 내용`, `alt 조건 … else … end` 분기.
- sequence의 참여자 표시 이름은 `participant ID as 이름`.

**상태 변화**
```
stateDiagram-v2
  [*] --> 접수
  접수 --> 검토 : 서류 완비
  검토 --> 승인
  검토 --> 반려 : 요건 미충족
  승인 --> [*]
```

**마인드맵**
```
mindmap
  root(("2027 전략"))
    성장
      신시장 진출
      신제품 3종
    수익성
      원가 -5%
    조직
      AI 역량 강화
```

### 렌더링 오류가 나면
화면에 빨간 오류 박스와 원본 코드가 표시된다. 위 규칙 1~5를 확인하고, 그래도 안 되면 노드를 줄여 단순화하거나 `rk-steps`로 대체한다.
